Traceroute 怎么看？它更适合找“在哪一段变差”

Traceroute 不是用来证明“某一跳就是故障”的简单工具，它更适合观察网络路径、路由变化和延迟从哪一段开始持续上升。

Traceroute 能看到什么

Traceroute 通过逐步增加数据包允许经过的跳数，观察通往目标的中间路由节点。它适合辅助定位网络路径问题，但显示出来的并不是每个业务请求的完整真实路径。

Windows 和 macOS 怎样运行

Windows 打开命令提示符，输入 tracert example.com；macOS 或 Linux 可在终端输入 traceroute example.com（部分系统可能需要先安装）。请将示例域名替换为你实际要检测的域名。

看到星号不要立即判断故障

中间路由器可能限制或不响应探测包，有些节点也会对探测流量使用不同优先级。只在中间一跳看到星号或延迟升高、后续节点却正常，通常不足以证明这一跳是故障点。

结合实际应用定位

最好同时记录目标是否真的打不开、Ping 丢包情况、故障发生时间和所用网络。不同探测协议、CDN 和负载均衡会使路径变化，必要时让服务提供商结合服务端日志判断。

一份输出应该怎么看

例如 Windows `tracert example.com` 出现第 1 跳 192.168.1.1（通常是本地网关）、第 2 跳 10.x.x.x、第 3 跳 `* * *`，但第 4 跳以及最终目标仍返回正常时间。这里第 3 跳不回应探测包，不足以证明网络在该节点中断。具体地址与跳数每次可能不同。

如何比较两个测试

记录同一目标、同一网络下正常与异常时段的结果，优先对比从哪一段开始持续丢失回复，以及最终业务访问是否同时出现问题。单个节点响应慢但后续正常时，不要直接归因于该节点。
