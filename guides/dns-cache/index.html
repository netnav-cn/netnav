改了 DNS 但没生效？可能只是缓存还在

更换 DNS 后立刻测试，有时仍会看到旧结果，因为浏览器、系统、路由器和解析器都可能缓存记录。

DNS 修改后没有生效，按现象排查 →

先搞清楚是谁在缓存

改 DNS 后还看到旧结果，不一定是设置失败。浏览器、操作系统、路由器以及上游解析器都可能保存 DNS 结果，域名记录本身也有 TTL。

什么时候值得清缓存

域名刚迁移、解析记录刚修改，或者你正在确认新的 DNS 设置是否生效时，清理本机缓存比较有用。平时没问题时没必要把清缓存当成“网络加速”步骤。

TTL 不是本机能强行跳过的

就算本地缓存已经清掉，上游递归解析器仍可能在 TTL 到期前返回旧记录。碰到这种情况，等一段时间再查，通常比反复重启路由器更有效。

怎么验证最省事

先用系统或命令行查看当前解析结果，再用一个独立 DNS 查询工具做对照。如果两边都已经返回新地址，说明问题大概率不在 DNS 缓存。

按顺序排查旧解析结果

  1. 先确认权威 DNS 记录是否已更新；如果权威结果仍旧，清本机缓存没有帮助。
  2. 用 nslookup example.com 或 dig example.com 查看当前解析地址，并记录查询服务器。
  3. 把结果与公共 DNS 查询服务对比。不同递归解析器在 TTL 到期前可能暂时不一致。
  4. 如果只有当前设备返回旧值，再考虑清理操作系统或浏览器缓存；不同系统的具体命令不同，使用与系统版本匹配的官方说明。

比如网站刚从旧主机迁到新主机，手机移动网络已经看到新地址、办公电脑仍访问旧站：先比较两端用的 DNS，别急着认为网站宕机。

哪些现象不应归咎于 DNS 缓存

域名已解析到正确地址，但浏览器显示旧页面，可能是 HTTP 缓存、CDN 缓存或服务端发布问题。可以先用无痕窗口、不同网络访问，并检查响应内容是否来自期望服务器。

如果你还在选择 DNS 服务，可以结合DNS 解析器的选择方法；若网页完全打不开，参考网站打不开的逐步检查。

先分清：缓存没过期，还是权威记录没改对

可以把查询分成两路：dig example.com A 查看设备当前使用的解析器结果；dig @1.1.1.1 example.com A 用指定公共解析器做对照。两边不同不一定是故障，还可能是缓存 TTL 未到期。示例域名要换成自己有权检查的域名。

如果你修改的是域名 DNS 托管服务商，先核对域名注册商处的 NS 委派和新权威服务器上记录是否一致；这和简单清除本机缓存不是一回事。如果多地结果暂时不同，参考如何选择 DNS 解析器。如果关心的是请求会不会绕过 VPN，则应该看DNS 泄漏检查，不要把两种问题混为一谈。
