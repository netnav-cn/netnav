网站出问题时，我通常先开这几个网络工具

排查网站故障时，把工具按问题类型分组，比收藏几十个链接更实用。

网站排查工具最好按问题来选

查 DNS 用 dig/在线 DNS 查询，查 TLS 配置用 SSL Labs，查页面性能用 PageSpeed Insights 或 WebPageTest，查 HTTP 头用 curl 或专门的 Header 工具。一个网站没必要包办所有检查。

自动评分只是线索

性能、安全 Header 或 页面检查工具给出的分数很适合发现问题，但不是业务目标本身。比如缓存策略、第三方脚本和安全策略都可能有合理例外。

重要变更要回到官方文档

浏览器、安全标准和搜索平台规则都会更新。涉及部署参数时，工具报告用来定位，最终配置以对应平台和标准文档为准。

网站异常时的最短检查路径

  1. 域名访问不了：先查询 A、AAAA、CNAME 等 DNS 记录，再确认解析指向的服务是否在线。
  2. 浏览器出现证书警告：检查证书域名、有效期和证书链；不要直接要求访客忽略警告。
  3. 页面打开慢：用 PageSpeed Insights 或 WebPageTest 观察主要瓶颈，再复核真实用户的加载体验。
  4. 只有某些地区打不开：分别测试不同网络和地区的 DNS、连通性以及 CDN 返回状态。

不要把检测分数当最终目标

同一个性能分数可能由完全不同的原因造成。与其只追求一个数字，不如记录变更前后的 LCP、INP、CLS 等指标，并确认真实页面功能没有因此受损。安全配置同样如此，Header 检测分数不能替代实际的权限与漏洞管理。

涉及页面加载的概念可参考测速结果的正确解读；若先要确认网站是不是整体故障，使用网站可用性排查流程。
